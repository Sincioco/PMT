PMT BDO Version 1.28 Deployment

Deployment baseline: PMT Database Version 1.27

Target: PMT Database Version 1.28

Version 1.28 changes Diagram and rich-text editor browser behavior. It does not add, remove, or rewrite tables, stored procedures, seed data, or user rows. The migration advances only the guarded database release marker.

The hashes use UTF-8 text normalized to LF line endings, so ordinary Windows and Unix Git checkouts produce the same result.

$ExpectedHashes = [ordered]@{
    'PMT_1.27_to_1.28.sql' = '5E6D52D865AA595CDD3C323ED46894050262B78B903CA533C44463AEC6D10C95'
    'PMT_1.27_to_1.28_All.sql' = '4F177F92492D3446B5D673FED12BFFA14C5A0FAF4E9E556C479631FF76912FB5'
}

foreach ($FileName in $ExpectedHashes.Keys) {
    $Text = [IO.File]::ReadAllText((Join-Path $PWD $FileName)) -replace "`r`n", "`n" -replace "`r", "`n"
    $Bytes = [Text.UTF8Encoding]::new($false).GetBytes($Text)
    $Sha256 = [Security.Cryptography.SHA256]::Create()
    try {
        $ActualHash = ([BitConverter]::ToString($Sha256.ComputeHash($Bytes))).Replace('-', '')
    }
    finally {
        $Sha256.Dispose()
    }
    if ($ActualHash -ne $ExpectedHashes[$FileName]) {
        throw "Hash mismatch for $FileName. Stop the deployment."
    }
}

Before Deployment

  1. Keep the application files and this migration folder from the same Git commit.
  2. Confirm the installed database reports PMT_DatabaseVersion = 1.27.
  3. Stop the IIS site or application pool and leave it stopped during migration and file replacement.
  4. Back up the PMT database, published application, configuration, and upload folder as one rollback set.
  5. Verify the SQL backup before continuing.

Run the Combined Migration

Open PowerShell in SQL\Migrations and run:

sqlcmd -S "<SQL SERVER OR SQL SERVER\INSTANCE>" -d PMT -E -b -I -i ".\PMT_1.27_to_1.28_All.sql"

For SQL authentication, replace -E with the approved credential arguments. In SQL Server Management Studio, enable Query > SQLCMD Mode and run the same combined file.

Expected completion messages:

PMT Database Version 1.28 migration completed without schema or data changes.
PMT combined database migration 1.27 to 1.28 completed.

Verify

USE [PMT];
GO

SELECT CONVERT(NVARCHAR(20), [value]) AS [PMT_DatabaseVersion]
FROM sys.extended_properties
WHERE [class] = 0
  AND [name] = N'PMT_DatabaseVersion';
GO

DBCC CHECKDB(N'PMT') WITH NO_INFOMSGS;
GO

The version query must return 1.28, and DBCC CHECKDB must report no errors. Compare the pre/post table row counts recorded with the backup; this migration must not change them.

Deploy the Application

  1. Deploy the matching Version 1.28 application files without overwriting production configuration or upload storage.
  2. Start the IIS site or application pool.
  3. Run the production-safe smoke checks for login, Documentation, Diagram, and Diagram 2.
  4. Press Ctrl+F5 once. The changed JavaScript and CSS URLs are cache-versioned.
Do not run rebuild or seed scripts against Production. If any migration or verification step fails, keep the application stopped and restore the matched database, application, configuration, and upload rollback set.

Build note: Version 1.28 contains no .NET source changes. A .NET recompile is not required for local browser testing; Ctrl+F5 is sufficient after the updated static files are present. Normal production publishing may still be used to create a complete deployment folder.
