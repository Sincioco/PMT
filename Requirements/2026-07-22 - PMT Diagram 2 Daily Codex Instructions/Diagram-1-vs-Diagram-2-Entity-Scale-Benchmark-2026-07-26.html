What Makes Diagram 1 Slow

  • Diagram 1 treats the saved SVG as the live read-only surface. On load it inserts a full SVG, parses embedded PMT metadata from that SVG, resolves entity overlap rules, binds relationship interactivity, and prepares the legacy zoom/pan surface. That grows expensive as the saved SVG crosses thousands of descendants.
  • It pays for everything as one main-thread job. SVG insertion, metadata parsing, relationship line preparation, and DOM binding all compete on the browser main thread. Once the PMT Schema clone reaches the +40 range, each extra entity and its few relationships add enough DOM and relationship work to push route readiness toward the cap.
  • The legacy route has no explicit renderer idle contract. Diagram 1 readiness must be inferred from visible DOM and busy flags. That makes it harder to split large work into measurable phases or to defer nonessential detail.
  • The cost curve is nonlinear near the threshold. The saved SVG descendant count rises roughly linearly, but relationship routing and DOM binding can introduce superlinear pauses because each additional connected entity increases the number of relationship candidates, hit targets, labels, and event-bound SVG nodes.

What Makes Diagram 2 Faster

  • Diagram 2 renders from normalized canonical state. It reads the same saved PMT Diagram metadata, but the renderer owns object and relationship maps instead of treating the exported SVG markup as the source of truth.
  • Keyed SVG nodes reduce churn. Objects and relationships are tracked by stable IDs, so the renderer can build predictable object, relationship, overlay, and diagnostic planes without rehydrating the full legacy read-only viewer stack.
  • The renderer exposes an idle boundary. The benchmark waits for window.__pmtDiagram2Renderer.whenIdle(), so the recorded time is tied to the renderer finishing its own work rather than to an inferred DOM condition.
  • Relationship rendering is isolated. Diagram 2 reports mounted object and relationship counts, frame duration, and SVG descendant counts. At the Diagram 1 failure row, it mounted 134 objects and 157 relationships with 2,998 SVG descendants and still finished in 322 ms.
  • It scales inside the current PMT route shell. The same PMT data, same saved documents, same local app, and same authenticated UI session were used. The difference is the Diagram 2 rendering path, not a different database or simplified data source.

  • Baseline: PMT's Database Schema, Blog 20, source file D:\Project Management Tool (PMT)\wwwroot\assets\docs\pmt-database-schema.svg.

  • Diagram 1 ready condition: selected read-only Diagram SVG visible, selected viewer not deferred, and viewport not busy.
  • Diagram 2 ready condition: selected Diagram 2 live SVG visible and whenIdle() resolved.
  • Timeout definition: a route that did not become usable inside 20.00 s was marked as timed out. Every shell command was kept below one minute.
